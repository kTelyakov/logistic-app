# AGENTS.md — инструкция агенту

Экран диспетчера на Vue 3 + TypeScript и заглушка сервера (см. `Frontend.md`).
Работа ведётся через OpenSpec: сначала change в `openspec/changes/`, потом реализация по `tasks.md`.
Архитектурные решения лежат в `openspec/config.yaml`. Не меняй их молча: нужен отдельный change.

## Команды

| Команда | Что делает | Статус |
|---|---|---|
| `make install` | `npm install` | работает |
| `make mock` | заглушка сервера | `mock-server` |
| `make dev` | экран (Vite) | работает |
| `make check` | типы, линтер, правила 1–3 | пока только `vue-tsc`; остальное в `code-rules-check` |
| `make test` | Vitest | `sync-core`, `tests-unit-e2e` |
| `make e2e` | Playwright на заглушке | `e2e-foundation`, `tests-unit-e2e` |
| `make perf` | прогон → `perf/report.md` | `perf` |

Цель, которая ещё не реализована, завершается ошибкой. Не превращай её в заглушку с кодом 0.
Перед тем как считать задачу выполненной, запусти `make check` и `make test` (когда они появятся).

## Структура

```
contract/            общий пакет: только типы и константы
mock/                заглушка сервера (Node + TS)
src/shared/          httpClient, ui, utils; не знает о модулях
src/modules/<module>/  api/ helpers/ utils/ store/ components/ *Container.vue index.ts
tests/e2e, tests/perf
```

FSD и тактический DDD не используем. Модули: `session`, `sync`, `vehicles`, `points`, `decisions`, `site-map`.

## Правила кода (проверяются в `make check`, нарушение — ошибка)

1. **Модули** (`rule-1`, проверка в `code-rules-check`). Код лежит в `src/modules/<module>/`. Импорт между модулями только через `index.ts` модуля-владельца. Циклов нет.
2. **Контейнеры и компоненты** (`rule-2`, проверка в `code-rules-check`). `*Container.vue` отвечает за запросы, состояние и ошибки. Компонент показывает данные из props и сообщает о действиях через `emit`. Запросов не делает, store не меняет. Компонент не импортирует `api/` и `store/`. Для сквозного контекста (`canCommand`, `siteTz`, `serverNow`) можно `inject`. Prop drilling решай вложенными контейнерами и слотами.
3. **HTTP и слои** (`rule-3`, проверка в `code-rules-check`). HTTP только в `api/` модуля через единый клиент `src/shared/http`. Бизнес-функции в `helpers/`, технические в `utils/`.
4. **Pinia** (`rule-4`). Только общее долгоживущее состояние. Функции, меняющие состояние store, называются с суффиксом `Mutator`.

## Запреты

- RxJS и другие реактивные библиотеки для потока данных, WebAssembly, zod и рантайм-валидаторы.
- FSD-слои, классы-агрегаты и репозитории из DDD.
- `v-html`. Текст `reason` выводится только как текст.
- Менять `contract/` без отдельного change. `contract/` не импортирует `src/` и `mock/`.
- Оптимистичные обновления. На экране состояние из ответа сервера (при 409 актуальное решение из тела ответа).
- Считать на клиенте очередь, ожидание, выигрыш и прочие показатели: они приходят с сервера.
- Брать время из часов браузера для отсчётов и устаревания: только время сервера (сдвиг из heartbeat). Показывать время в поясе площадки из `/api/me`.
- Класть машины в Pinia или делать их реактивными.
- Запросы к внешним адресам: шрифты, иконки и подложка только в сборке.
- Менять или удалять `data-testid`: на них опираются e2e-проверки.

## Контракт (`contract/`)

- Только типы и константы, без рантайм-зависимостей и валидаторов. Единственный вход: `contract/src/index.ts`.
- Заглушка и экран импортируют `@dispatch/contract`. Своих копий типов не заводить.
- Менять контракт можно только отдельным change в OpenSpec. «Подогнать тип под реализацию» запрещено.
- `contract/` не импортирует `src/` и `mock/` (проверка появится в `code-rules-check`).
- Проверка типов контракта: `tests/contract/contract.typetest.ts`, выполняется в `make check`.
- Тело ответа 403 (`ForbiddenBody { message }`) в задании не описано. Это наше уточнение, оно общее для заглушки и экрана.

## Поток данных (кратко)

WebSocket, разбор JSON и ядро `seq` живут в Web Worker. Ядро это чистый редьюсер без обращения к `Worker`.
Машины хранятся в типизированных массивах (арена, слот на машину) вне реактивности и рисуются голым WebGL2 (instanced).
Команды: `Idempotency-Key` создаётся один раз на намерение и повторяется при ретрае; `If-Match` с `version`.

## Как работать

1. Новая работа начинается с change в OpenSpec. Не пиши код без задачи в `tasks.md`.
2. Одна задача — один проверяемый результат. Отмечай `- [x]` только после проверки.
3. Если реализация расходится со спекой или дизайном, остановись и предложи обновить артефакты.
4. Если не уверен, спроси. Не угадывай.
