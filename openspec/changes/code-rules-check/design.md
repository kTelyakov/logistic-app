# Design

## Context

Правила и структура модулей зафиксированы в AGENTS.md. Проверка должна ловить нарушение «как есть», без ручной настройки списков. См. proposal.md.

## Goals / Non-Goals

**Goals:** каждое правило имеет автоматическую проверку и тест на нарушение; существующий код чист.

**Non-Goals:** смысловая проверка тела функций, форматирование.

## Decisions

- **Локальный плагин ESLint, а не `eslint-plugin-boundaries`:** правила короткие и точно отражают текст задания (импорт только через `index.ts`; `shared` не знает о модулях; слои `api`, `helpers`, `utils`). Свои правила дают понятные сообщения на русском со ссылкой на номер правила и не требуют настройки «элементов» и «матрицы связей». Плюс: те же правила работают и для `.vue` через `vue-eslint-parser`.
- **Циклы отдельным скриптом по TypeScript API:** ESLint-правило цикла требует знать весь граф; скрипт строит граф файлов `src` (разбор импортов `.ts` и `<script>` из `.vue`, разрешение `@/` и относительных путей), ищет сильно связные компоненты и сообщает путь цикла. Модульные циклы видны как циклы через `index.ts`. `import type` тоже считается: тип-цикл остаётся циклом.
- **Область действия `src/**`:** e2e и инструменты могут обращаться вглубь модулей (Playwright не импортирует `.vue`); это не нарушение архитектуры приложения.
- **Компонент это `.vue` не `*Container.vue`:** критерий из задания. Запреты по импортам (`api`, store, общий клиент, Pinia), вызовам `fetch`, сети и `*Mutator`.
- **Слои как структурные запреты:** `helpers` без `api`, store и Vue; `utils` без модулей, `helpers`, `api`, store; `api` без компонентов и store. Смысл «бизнес» и «технические» проверяется слоями, не телом функции.
- **Правило 4 как бонус:** задание проверяет 1–3, но `defineStore` вне `store/` и мутаторы без суффикса ловятся теми же средствами; издержки нулевые.
- **Негативные тесты:** каждое правило имеет файл с нарушением и файл с допустимым кодом; тест прогоняет ESLint по тексту с виртуальным путём. Для циклов статические фикстуры в `tools/lint/fixtures`. Фикстуры исключены из линтера.

## Risks / Trade-offs

- [Правило ложно срабатывает на легитимный код] → тесты на допустимые случаи; сообщение называет правило и способ исправить.
- [Обход через динамический `import()` или `require`] → правила смотрят и на `ImportExpression`.
