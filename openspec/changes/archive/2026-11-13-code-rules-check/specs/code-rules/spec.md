# Spec Delta

## Purpose
Архитектурные правила кода проверяются автоматически: нарушение даёт ошибку `make check`.

## ADDED Requirements

### Requirement: Границы модулей (правило 1)
`make check` SHALL завершаться ошибкой, если файл в `src/modules/<A>/` импортирует файл из другого модуля `<B>` не через его `index.ts`, если `src/shared` импортирует модуль или `src/app`, или если модуль импортирует `src/app`. Импорт модуля через `@/modules/<B>` SHALL быть разрешён.

#### Scenario: Глубокий импорт чужого модуля
- **WHEN** файл модуля A импортирует `@/modules/B/store/bStore`
- **THEN** `make check` SHALL завершиться ошибкой с указанием правила 1

#### Scenario: Импорт через публичный вход
- **WHEN** файл модуля A импортирует `@/modules/B`
- **THEN** `make check` SHALL не сообщать об ошибке

### Requirement: Циклов импортов нет (правило 1)
`make check` SHALL завершаться ошибкой при цикле импортов между файлами `src`, в том числе между модулями через их `index.ts`.

#### Scenario: Цикл между двумя файлами
- **WHEN** файл A импортирует B, а B импортирует A
- **THEN** `make check` SHALL завершиться ошибкой с перечислением цикла

### Requirement: Компонент не делает запросов и не меняет store (правило 2)
`make check` SHALL завершаться ошибкой, если `.vue` файл, не являющийся `*Container.vue`, импортирует слой `api`, общий HTTP-клиент, store или Pinia, вызывает `fetch`, открывает сеть или вызывает функцию с суффиксом `Mutator`. Контейнеры SHALL быть свободны от этого ограничения.

#### Scenario: Компонент вызывает fetch
- **WHEN** компонент вызывает `fetch(...)`
- **THEN** `make check` SHALL завершиться ошибкой с указанием правила 2

#### Scenario: Компонент меняет store
- **WHEN** компонент импортирует store и вызывает его мутатор
- **THEN** `make check` SHALL завершиться ошибкой

#### Scenario: Контейнер делает запросы
- **WHEN** контейнер импортирует `api` и store
- **THEN** `make check` SHALL не сообщать об ошибке

### Requirement: HTTP только в слое api через общий клиент (правило 3)
`make check` SHALL завершаться ошибкой, если `fetch`, `XMLHttpRequest`, `axios`, `WebSocket` или функция запросов общего клиента используются вне слоя `api` (и вне самого клиента), а также если слой `helpers` импортирует `api`, store, Vue или Pinia, слой `utils` импортирует модули, `helpers`, `api` или store, слой `api` импортирует компоненты или store.

#### Scenario: fetch в обычном файле
- **WHEN** файл вне `api/` и вне клиента вызывает `fetch`
- **THEN** `make check` SHALL завершиться ошибкой с указанием правила 3

#### Scenario: Запрос из helpers
- **WHEN** файл в `helpers/` импортирует `api/`
- **THEN** `make check` SHALL завершиться ошибкой

#### Scenario: Запрос в api через общий клиент
- **WHEN** файл в `api/` использует общий клиент
- **THEN** `make check` SHALL не сообщать об ошибке

### Requirement: Pinia и мутаторы (правило 4)
`make check` SHALL завершаться ошибкой, если `defineStore` вызывается вне каталога `store/`, или если функция store, меняющая состояние, не оканчивается на `Mutator`.

#### Scenario: Мутирующая функция без суффикса
- **WHEN** функция store присваивает значение состоянию, а её имя не оканчивается на `Mutator`
- **THEN** `make check` SHALL завершиться ошибкой с указанием правила 4

### Requirement: Нарушение есть ошибка
Все правила SHALL иметь уровень `error`, `make check` SHALL возвращать ненулевой код при любом нарушении, а `v-html` SHALL быть запрещён.

#### Scenario: v-html
- **WHEN** шаблон использует `v-html`
- **THEN** `make check` SHALL завершиться ошибкой
