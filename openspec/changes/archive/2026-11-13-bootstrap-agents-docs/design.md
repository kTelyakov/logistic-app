# Design

## Context

Репозиторий пустой (только `Frontend.md` и `openspec/`). Решения по архитектуре зафиксированы в `openspec/config.yaml`. См. proposal.md: зачем нужен каркас.

## Goals / Non-Goals

**Goals:**
- `make dev` поднимает пустой экран; остальные цели существуют и честно сообщают «не реализовано».
- `AGENTS.md` читается агентом как единственный источник правил и команд.

**Non-Goals:**
- Любая предметная логика.

## Decisions

- **npm workspaces** (`contract`, `mock`) вместо pnpm/turborepo: меньше инструментов, достаточно для двух пакетов. Корень остаётся пакетом фронтенда.
- **Vite** как сборщик: нативная поддержка Vue 3 и Web Worker (`new Worker(new URL(...), { type: 'module' })`).
- **Makefile тонкий**: каждая цель вызывает `npm run <script>`; логика в скриптах, не в make. Нереализованные цели падают с кодом 1, чтобы CI не давал ложного «зелёного».
- **TypeScript strict** и `noUncheckedIndexedAccess`: типизированные массивы и индексы по слотам иначе тихо дают `undefined`.
- **AGENTS.md** ссылается на проверки по именам правил (`rule-1..4`), чтобы связь «правило, проверка» не терялась, когда появится `code-rules-check`.

## Risks / Trade-offs

- [Правила в AGENTS.md расходятся с реальными проверками] → в `code-rules-check` добавить тест, что каждое правило из AGENTS.md имеет проверку; пока ссылки помечены «появится в code-rules-check».
- [Заглушки целей Makefile забудут заменить] → падают с ошибкой, `final-docs` проверяет, что ни одна цель не осталась заглушкой.
