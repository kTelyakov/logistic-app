# Design

## Context

Контракт берётся из Frontend.md (часть 1, «Контракт»). Заглушка на Node + TS, поэтому оба потребителя пишутся на TypeScript и могут делить типы напрямую. См. proposal.md: зачем нужен пакет.

## Goals / Non-Goals

**Goals:**
- Одна точка входа, типы и константы, нулевые зависимости.
- Любое расхождение заглушки и клиента с контрактом видно `tsc`.

**Non-Goals:**
- Проверка данных в рантайме.

## Decisions

- **Типы вручную, без zod и генерации:** меньше зависимостей и церемониала для задания; граница доверяет серверу, неизвестный `type` сообщения клиент просто игнорирует.
- **`as const` объекты и литеральные объединения вместо `enum`:** нет рантайм-кода от `enum`, типы выводятся из констант.
- **Размеченное объединение `WsMessage`:** позволяет исчерпывающий `switch` в ядре синхронизации.
- **`workspace:*`-зависимость через npm workspaces:** потребители импортируют `@dispatch/contract`, сборка не нужна (импорт TS-исходников; для Node-заглушки запускается через `tsx`).

## Risks / Trade-offs

- [Сервер отдаёт данные не по типам, а типы это не поймают] → `reason` выводится только как текст; на границе обрабатываем только то, что влияет на синхронизацию (`seq`, `type`).
- [Агент правит контракт «под реализацию»] → запрет в AGENTS.md, изменения только отдельным change.
