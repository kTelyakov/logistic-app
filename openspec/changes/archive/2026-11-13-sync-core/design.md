# Design

## Context

Протокол и сообщения заданы в Frontend.md и `contract/`. Ядро будет работать в Web Worker (см. `sync-worker`), но не знает о нём. См. proposal.md.

## Goals / Non-Goals

**Goals:** сходимость к состоянию сервера при любых комбинациях drop/dup/reorder/reset; ядро детерминировано и тестируется без таймеров и сети.

**Non-Goals:** доставка эффектов, ретраи по сети, реальные часы.

## Decisions

- **Детерминированный автомат с эффектами:** `applyEvent(state, event, config)` изменяет `state` и возвращает список эффектов (`fetchSnapshot`, `openSocket`, `replace`, `apply`), которые исполняет оболочка. Состояние изменяемое: при 15 000 сообщений в секунду копировать буфер на каждом событии нельзя. Ядро детерминировано, не знает про сеть, таймеры и часы, поэтому тестируется без моков. Альтернатива «RxJS» отвергнута (см. config.yaml): автомат читается и тестируется проще.
- **События пачками:** оболочка передаёт сообщения массивом (`messages`), ядро отдаёт одну пачку применённых.
- **Время приходит событием:** каждое событие несёт `now` (монотонные миллисекунды). Таймеры живут в оболочке, которая раз в ~100 мс шлёт `tick`. Окно перестановки и задержки повтора проверяются по `now`.
- **Окно перестановки (по умолчанию 500 мс):** опережающее сообщение ждёт недостающее; дольше это уже потеря, и дешевле взять снимок, чем гадать. Альтернатива «сразу снимок при любой дыре» ломается на нормальных перестановках.
- **Во время загрузки снимка сообщения копятся в буфере, а не применяются:** прежнее состояние остаётся на экране с признаком переподключения, новое заменяет его целиком. Это исключает смесь старого и нового.
- **Подключение после снимка идёт с `since` последнего применённого `seq`:** повторы отсекает правило `seq ≤ last`, поэтому гонка между снимком и потоком безопасна.
- **Обрыв соединения не требует снимка:** переподключение с `since`; если сервер ответит `reset`, сработает ветка `reset`.
- **Сдвиг часов:** `offset = serverAt - localWall`, берётся максимум по последним замерам (наименьшая задержка). Время в событиях ядра не участвует: сдвиг считает оболочка через `serverClock`.
- **Ограничение буфера (200 000 сообщений):** защита от неограниченного роста; переполнение вызывает снимок.

## Risks / Trade-offs

- [Окно слишком короткое: лишние снимки] → значение в конфиге; снимок безопасен, цена мала.
- [Окно слишком длинное: экран отстаёт] → 500 мс при heartbeat 5 с незаметно для диспетчера.
- [Бесконечный цикл снимков при постоянных потерях] → задержка между запросами снимка (`resyncCooldownMs`).
