# Design

## Context

Заглушка запускается через `make mock` на Node + TypeScript и разделяет типы с фронтендом через `@dispatch/contract`. Режимы отказов должны включаться переменными окружения, чтобы e2e и perf могли запускать разные конфигурации.

## Goals / Non-Goals

**Goals:**
- Детерминируемая отказоустойчивость: все FAULTS воспроизводимы (seed из окружения).
- Выдерживать до 15000 машин раз в секунду без собственных задержек.

**Non-Goals:**
- Реалистичное движение, масштабирование, персистентность.

## Decisions

- **`ws` + встроенный `http`** вместо Fastify: две зависимости, нужен только простой роутинг по пяти путям; меньше поверхности для ревью. Fastify оправдан, если роутинг разрастётся.
- **Единый журнал событий:** все изменения состояния пишутся как `seq`-события в кольцевой буфер; снимок и поток строятся из него, что гарантирует согласованность `since` и `reset`.
- **FAULTS как слой над отправкой:** состояние и журнал истинные; `drop`, `dup`, `reorder` применяются только при записи в сокет. `/debug/state` читает истинное состояние, мимо слоя отказов.
- **Идемпотентность:** таблица `Idempotency-Key → ответ и счётчик выполнений`; для `slow` часть команд исполняется до задержки ответа.
- **Нагрузка:** для больших `LOAD` обновления машин копятся за тик и отправляются одним проходом по сокетам (без `JSON.stringify` на каждую пару машина-клиент: сообщение сериализуется один раз и рассылается).
- **Время:** сервер использует свои часы; `at` и heartbeat независимы от браузера (проверка сдвига на клиенте).
- **Запуск:** `tsx` без отдельной сборки.

## Risks / Trade-offs

- [Мок сам станет узким местом на LOAD=15000] → батчинг и однократная сериализация; отдельная проверка в `perf`.
- [Журнал растёт без границы] → кольцевой буфер ограниченного размера; выход за его пределы даёт `reset`, что и нужно для проверки.
- [Недетерминированные отказы дают нестабильные e2e] → seed в `FAULT_SEED`, по умолчанию фиксированный.
